# CryptunaPriceWidget

Python 3.10+, без сторонних зависимостей. Фиксированный список, не автоматический топ:

- Страница 1: BTC, ETH, BNB, XRP, SUI.
- Страница 2: SOL, TRX, HYPE, ZEC, DOGE.

Монеты отображаются в указанном порядке; рядом остаётся настоящий cmc_rank. USDT/USDC отсутствуют. Буквенные значки, без кита, «закреплена» и caption. Лампочка постоянно пульсирует зелёный/чёрный и не свидетельствует о свежести данных. Подпись «Получено …», без CMC.

## Запуск

```zsh
git pull --ff-only
python3 bot.py
```

BOT_TOKEN обязателен; ALLOWED_USER_ID необязателен. Если токен не задан:

```zsh
read -r -s 'BOT_TOKEN?Вставь токен бота: '; echo
export BOT_TOKEN
python3 bot.py
```

Токен не публикуйте. `.env` автоматически не читается. Отправьте новый `/widget` или `/prices`, чтобы получить новую вёрстку. Старые HTML-сообщения не меняются. Запускайте один процесс на токен/каталог, webhook сам не удаляется.

## Один пакетный запрос на десять монет

CMC endpoint: `https://pro-api.coinmarketcap.com/public-api/v3/cryptocurrency/quotes/latest`.

Параметры:

```
slug=bitcoin,ethereum,bnb,xrp,sui,solana,tron,hyperliquid,zcash,dogecoin
convert=USD
```

Один HTTP-запрос получает все десять котировок. Listings/latest, загрузка топ-100, map, metadata, CDN и отдельный запрос SUI не используются. Slug выбран вместо неоднозначного тикера. Ответ проверяется на наличие всех десяти slug и соответствующих символов до замены кэша. Неполный или некорректный ответ сохраняет предыдущий снимок, а не выдаёт чужую монету.

## Только по запросу пользователя

Фоновый сборщик удалён. Нет запросов котировок при старте, в простое, при открытии сообщения, листании страниц, /start или /help. Только /widget и /prices проверяют общий снимок под SEND_LOCK:

1. Криптоснимок младше 10 секунд — выдача из памяти.
2. Старше — одна попытка quotes/latest, если позволяют общий limiter и cooldown.
3. Ошибка, cooldown или лимит — предыдущие цены с прежним временем получения.
4. Coinbase USD/RUB обновляется по пользовательскому запросу не чаще одного раза в 60 секунд.

Повтор после ошибки только по следующей команде, без таймера. До первого успешного снимка — прочерки. Локальная анимация и watchPublicData опрашивают только Telegram, не CMC. Без команд пользователей автообновления каждые 10 секунд больше нет. Обновлённый общий shared widget может обновить уже отправленные копии. Одинаковые снимки лишний раз не публикуются.

## Лимит и сохранение

Один потокобезопасный RateLimiter: не более 50 попыток CMC за скользящие 60 секунд, включая неудачные. Cache hits не расходуют квоту. TTL/single-flight убирают дубликаты. При 429 учитывается Retry-After, действует backoff с jitter (минимум 60 с при 429). Провайдеры имеют отдельные cooldown. Это защитный предел нашего процесса, не гарантия CMC принять 50 keyless-запросов: общий IP может ограничиваться раньше.

Лимитер и response cache в памяти одного процесса, при перезапуске сбрасываются. runtime.json сохраняет последний снимок, время и ID shared widget без токена; исключён из Git. При миграции сохранённые котировки используются только если присутствуют все десять нужных активов с правильными slug; иначе ожидается новый ответ. Состояние записывается до отправки в Telegram, чтобы успешные котировки не потерялись из-за сбоя доставки.

Для реплик или общей квоты через рестарт нужен внешний limiter. runtime.json пока рядом с bot.py — постоянный диск Amvera отдельно не адаптирован. TLS-проверка включена, кэш не устраняет сетевые обрывы. USD/RUB справочный Coinbase, не курс ЦБ/банка. Время получения не равно времени сделки. Exactly-once не обещается.

## Тесты

```sh
python3 -m unittest -v
```

15 mock-тестов прошли: точный список и порядок, отсутствие/подмена актива, один quotes-запрос с десятью slug, кэш, скользящее окно и конкурентная квота, учёт неудач, cooldown/fallback, 20 пользовательских команд из кэша, миграция, формат и размер состояния, отсутствие фонового сборщика. Живой запрос CMC и Telegram end-to-end при подготовке не проверялись.
