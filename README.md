# WidgetTgBot

Минимальный Telegram-бот на Python 3.10+ без сторонних зависимостей. По команде `/widget` отправляет настоящий HTML-виджет через `sendWidget`, а не Mini App и не сообщение с `parse_mode=HTML`. Кнопка +1 меняет число непосредственно внутри сообщения.

## Запуск

1. Создайте бота у @BotFather командой `/newbot` и получите токен. Никому не отправляйте токен и не добавляйте его в Git.
2. Клонируйте репозиторий и перейдите в каталог:

```sh
git clone https://github.com/AndreyErmol/WidgetTgBot.git
cd WidgetTgBot
```

3. Передайте токен через переменную окружения. В Bash/Zsh можно ввести его без записи значения в историю команд:

```sh
read -r -s -p 'BOT_TOKEN: ' BOT_TOKEN; echo
export BOT_TOKEN
python3 bot.py
```

Если shell не поддерживает `read -p`, используйте его штатный способ задания переменной окружения. Для PowerShell:

```powershell
$secret = Read-Host 'BOT_TOKEN' -AsSecureString
$env:BOT_TOKEN = [System.Net.NetworkCredential]::new('', $secret).Password
python bot.py
```

4. Откройте личный чат с ботом, нажмите Start и отправьте `/widget`.
5. Нажимайте +1 внутри сообщения. Остановка бота: Ctrl+C.

Необязательно: задайте `ALLOWED_USER_ID` равным своему числовому Telegram user ID, чтобы бот отвечал только вам. Если переменная отсутствует или равна 0, бот доступен всем пользователям в личных чатах.

Бот читает переменные окружения; файл `.env` автоматически НЕ загружается. Установка pip-пакетов не нужна. Работает через long polling, поэтому публичный сервер, домен и HTTPS-вебхук не требуются. Запускайте только один экземпляр на токен. Если уже настроен webhook, программа завершится с сообщением, не удаляя его самостоятельно.

## Как устроено

- `/start`, `/help`: инструкция.
- `/widget`: новый HTML-виджет со счётчиком 0.
- Python вызывает `getUpdates` и `sendWidget` напрямую по HTTPS с JSON.
- `widget.html` содержит весь HTML, CSS и JavaScript; внешних ресурсов нет.
- Кнопка меняет DOM локально, не вызывает `TelegramWidget.request()` и не требует `allow_queries`.
- Счётчик демонстрационный: хранится только в памяти текущего экземпляра виджета. При пересоздании виджета клиентом, например при повторном открытии сообщения, начинается с 0. Никакого сохранения между устройствами или серверного состояния нет.
- Для постоянного счётчика нужен отдельный вариант с `allow_queries`, `widget_query`, `answerWidgetQuery`, хранилищем и `editMessageWidgetData`.
- Перед запуском проверяются лимиты HTML: 32768 байт UTF-8 и 4096 байт после zlib уровня 9, а также отсутствие NUL.

## Ограничения и диагностика

По официальному руководству на момент реализации production поддерживает виджеты только в личном чате с ботом. Каналы и группы для этой демонстрации не поддерживаются. Клиент без поддержки виджетов покажет неподдерживаемое вложение и подпись; используйте актуальный клиент с поддержкой widgets.

Если `sendWidget` недоступен или Telegram отклоняет запрос, смотрите описание ошибки в консоли. Бот не подменяет виджет обычной inline-кнопкой. Повторные `/widget` создают отдельные сообщения. После перезапуска возможна повторная обработка последнего обновления: offset хранится в памяти; это простой демонстрационный бот, не exactly-once обработчик.

Живой end-to-end тест с реальным токеном при подготовке кода не выполнялся.
